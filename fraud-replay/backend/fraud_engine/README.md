# Fraud Engine — модуль №3 Fraud Replay

Автономный Python 3.11+ модуль. Все примеры синтетические. Для анализа интернет не нужен; зависимости устанавливаются заранее. Frontend, сервер и база данных не включены.

## Установка и запуск

Из каталога `fraud_engine_module`:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
python -m pip install -r backend/fraud_engine/requirements.txt
python -m pytest -q
python -m backend.fraud_engine.cli --input data/suspicious_transactions.csv --output result.json
```

CLI возвращает код 0 при успехе и 2 при ошибке данных или файлов. Выход — UTF-8 JSON, объяснения на русском.

## Вход и интеграция

CSV UTF-8 с заголовком `transaction_id,timestamp,sender,receiver,amount`. ID и счета — непустые строки без крайних пробелов; ID уникален глобально. Сумма конечная и строго положительная, в одной согласованной валюте/единице. Время ISO 8601 обязательно со временем суток. Даты с поясами приводятся к UTC; смешивание дат с поясом и без запрещено. Дополнительные поля игнорируются. Некорректный пакет отклоняется целиком через `ValidationError` (подкласс `ValueError`); файловые ошибки — `OSError`.

```python
from backend.fraud_engine import analyze_transactions, analyze_csv

result = analyze_transactions([
    {"transaction_id": "TX001", "timestamp": "2026-11-17T14:02:00",
     "sender": "A001", "receiver": "B001", "amount": 800000}
])
result = analyze_csv("data/suspicious_transactions.csv")
```

Для backend добавьте каталог модуля в проект или PYTHONPATH. Пример интеграции в существующий FastAPI команды (FastAPI не является зависимостью модуля):

```python
from fastapi import HTTPException
from backend.fraud_engine import analyze_transactions, ValidationError

@app.post("/fraud/analyze")  # app уже создан командой backend
def analyze(payload: list[dict]):
    try:
        return analyze_transactions(payload)
    except ValidationError as exc:
        raise HTTPException(status_code=422, detail=str(exc)) from exc
```

## Правила и риск

| Правило | Условие | Вес |
|---|---|---|
| large | Сумма ≥ 5 медиан предыдущих исходящих операций при наличии ≥ 5 операций истории | 35 |
| large, мало истории | Демонстрационный порог ≥ 500 000; явно указан в объяснении | 35 |
| burst | ≥ 4 исходящих перевода за ≤ 5 минут, включая повторные переводы одному получателю | 25 |
| chain | ≥ 3 направленных перевода A→B→C→D; каждый следующий строго позже, ≤ 15 минут после предыдущего; сумма 70–100% предыдущей | 60 |
| fanout | Исходящие переводы ≥ 3 разным получателям за ≤ 10 минут | 40 |

История включает только операции из входного пакета, строго предшествующие по времени. Одновременные переводы не влияют на историю друг друга. Окна включают обе границы; серия и распределение допускают одинаковые timestamps. Цепочки используют NetworkX MultiDiGraph, сохраняющий повторные переводы; глубина по умолчанию 6 переводов (настраивается в `find_chains`, максимум 12). Повторное посещение счета запрещено, циклы не считаются цепочками. Окно 15 минут применяется к каждому шагу, а не ко всей цепочке.

Срабатывания объединяются в кейсы по общим transaction_id, транзитивно. Совпадение счета само по себе кейсы не объединяет. Каждое правило даёт вес один раз на кейс; сумма ограничена 100. Уровни: low 0–29, medium 30–59, high 60–100. Это детерминированный приоритет ручной проверки, **не вероятность мошенничества**. Даже low может быть подозрительным кейсом.

## JSON для Backend и Replay

`cases` содержит `case_id` (FR-001 и далее), `risk_score`, `risk_level`, русские `reasons`, `transaction_ids`, `timeline`, `graph`. Timeline сортируется по времени и затем ID. Graph содержит все счета кейса (`nodes: [{id}]`) и каждый перевод (`edges: [{id, source, target, amount}]`). Исходные ID сохраняются. Времена сериализуются в ISO 8601; суммы — JSON числа. `summary` содержит `total_transactions`, число уникальных подозрительных операций `suspicious_transactions` и `cases_count`. Если срабатываний нет, `cases: []`. Порядок входных строк не влияет на результат; ID кейсов стабильны для одинакового набора данных, но могут измениться при добавлении операций.

## Демоданные и ограничения

`normal_transactions.csv`: 30 независимых небольших переводов, ожидается 0 кейсов.
`suspicious_transactions.csv`: TX001–TX004 — крупная цепочка; BURST01–04 — повторные переводы; FAN01–03 — распределение; HIST01–05 — история и HIST_BIG — превышение её медианы; остальные 17 переводов — фон. Всего 34 операции. Сценарии независимы, ожидается 4 кейса и 12 подозрительных операций.

Эвристики не обучены и требуют калибровки по валюте, продукту и реальной истории. Нет балансов, валютной конвертации, внешних списков, профиля клиента или выявления циклического отмывания. Деньги в цепочке сопоставляются по времени и сумме, реальная принадлежность средств не доказана. Данные хранятся в памяти; число ветвлений графа может экспоненциально расти, ограничение глубины не ограничивает ширину. Для больших потоков нужны лимиты пакета и отдельная обработка. Дробные суммы после проверки преобразуются в float для JSON, что может округлять точные денежные значения; для банковского контура передавайте целые минимальные единицы валюты. Тесты проверяют синтетические сценарии, не качество на реальном банковском потоке.
